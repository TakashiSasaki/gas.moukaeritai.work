1. System Architecture (Hybrid Loading)

ARCH Component Separation

  • Index.html: Structure and logic. No CSS. Uses include('Stylesheet'). Contains UI Mocks.
  • Stylesheet.html: All CSS rules. Disconnected in Preview to keep logic lightweight.
  • JavaScript.html: Real production logic overriding global window functions.
  • Code.gs: Server-side Drive API logic and include() helper.

2. Drive API v3 Constraints

CRITICAL Update Signature

Moving files: Drive.Files.update({}, fileId, null, {addParents, removeParents}). 3rd arg MUST be null.

API Forbidden q-Fields

  • size: ❌ Forbidden in search query. Filter post-fetch.
  • description: ❌ Forbidden. Use fullText contains.
  • ' (Quote): ⚠️ Always escape user input as \'.

5. Concurrency & Performance Strategy

PERF Sequential Batch Processing (UPDATED)

To optimize execution while maintaining UI responsiveness and avoiding script timeouts:

  • Client-Side Iteration: The client iterates over selected file IDs.
  • Batching: IDs are grouped into chunks of 10.
  • Single Request per Batch: Send one request (10 files) at a time to the server.
  • Feedback: Progress bar and logs are updated after each batch (every 10 files).

UI State Rules

  • Reset-First: Disable/hide all groups before enabling the active mode.
  • Checkboxes: Rows MUST set value="${file.id}".
  • Smart Picker: If ID exists, open its parent folder in the dialog.
