This document is the Absolute Source of Truth. All agents MUST strictly follow these rules to avoid regressions in error handling, UI state, and API compliance.

1. System Architecture (The Modular Pattern)

ARCH Component Responsibility

  • Router.gs: Handles doGet(e) and serves pages based on ?p=... parameter. Required for future extensibility (e.g., Settings page).
  • Index.html: Logic Hub. Contains DOM, Global State Declarations, and Mock functions. CSS is FORBIDDEN here.
  • Stylesheet.html: Dedicated CSS. Included via <?!= include('Stylesheet'); ?>. Ignored in Gemini Preview.
  • JavaScript.html: Production Logic. Overrides window mocks.
  • Code.gs: Backend API logic (v3). Single-purpose functions only.

2. Global State & Scoping Rules

CRITICAL Window-Bound State

Because JavaScript.html is loaded into the template separately, shared state variables (e.g., currentFolderIds, fileNamesMap) MUST be explicitly attached to the window object in Index.html.

// CORRECT in Index.html
window.currentFolderIds = []; 
window.fileNamesMap = {};

// INCORRECT (may cause 'undefined' in JavaScript.html)
let currentFolderIds = [];

3. Concurrency & Performance (The 5x5 Pattern)

PERF Parallel Batching Standards

  • Parameters: 5 concurrent workers, batch size of 5 items per request.
  • Startup Jitter: Each worker MUST wait for a random duration (0ms to 3000ms) before the first request. This prevents the "Thundering Herd" effect on server resources.
  • Analyze Concurrency: "Analyze Folders" must also use parallel workers (Limit: 3) to prevent UI blocking during massive folder counts.

4. Robustness & Error Mitigation

CRITICAL Undefined Error Handling

GAS google.script.run can fail non-deterministically (network blips), returning an undefined error object. Implementation requirements:

  • Sanitization: runWithRetry must sanitize errors. If err.message is missing, fallback to "Unknown Network or Server Error".
  • Jittered Retry: SERVER_BUSY retries must wait 1500ms + random(1000ms) to de-synchronize retrying clients.

6. UI Implementation Rules

UI State & Modals

  • Reset-First Rule: Before enabling a specific input group (e.g., Date Year mode), DISABLE and HIDE all others in that set.
  • Dual-Lock: Apply both the disabled HTML attribute AND .input-disabled CSS class.
  • Row Checkboxes: MUST include value="${f.id}". If missing, selection counts will fail.
  • Dynamic Init: Dropdowns like "Year Selection" (2010 to Present) MUST be generated dynamically in initApp to prevent maintenance rot.
  • Elapsed Time: Every batch move MUST display elapsed seconds on the primary action button.
